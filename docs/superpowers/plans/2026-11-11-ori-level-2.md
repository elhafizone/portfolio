# ORI Level 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ORI roams the viewport freely, follows scroll with lag, and opens a bilingual guide bubble (chips + AI free text) that recommends only the site's projects/services.

**Architecture:** Pure logic in `lib/ori/*.ts` (relative imports only, so `node --test` runs them with Node 24 type stripping). `OriCompanion` owns the three.js scene and moves its wrapper with a compositor-only `transform`; `OriGuide` (lazy) owns the bubble. They talk through `window` CustomEvents defined in `lib/ori/bus.ts`. `app/api/ori/route.ts` calls Claude Haiku with the server-built catalogue.

**Tech Stack:** Next.js 15 app router, React 19, three 0.170, Tailwind, `@anthropic-ai/sdk` (server only), `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-11-ori-level-2-design.md`

## Global Constraints

- Model `claude-haiku-5-5`; `max_tokens` 300; key `ANTHROPIC_API_KEY` (server only, added to `.env.example`); no key → free-text box hidden.
- Limits: 10 messages / hour / IP; 300 requests / day global; input ≤ 300 chars; history ≤ 6 turns; ≤ 2 items per reply.
- Copy lives in `data/content/ar.ts` / `en.ts` under a new `ori` key; Arabic default RTL; logical CSS only.
- No new first-load JS: guide is `next/dynamic` / `import()` after intro, like the scene.
- Reduced motion: no roaming/scroll lag; bubble still works.
- Never push or deploy.

## Review Focus

- Bubble open near a viewport edge (RTL and LTR, 360px wide phone): bubble fully on screen, ORI parked, not covering it.
- Rapid repeated chip clicks / sending while a request is pending: one request in flight, input disabled-by-state but focusable, no duplicate cards.
- API returns non-JSON / unknown ids / 429 / network error: friendly fallback + chips, never a raw error.
- Window resize or orientation change while roaming: waypoint re-clamped, ORI never stays off-screen.
- Tab hidden then shown: no huge dt jump (dt already clamped to 0.05) and no backlog of travel.

### Task 1: Roaming movement

**Files:**
- Create: `lib/ori/roam.ts`, `lib/ori/roam.test.ts`, `lib/ori/bus.ts`
- Modify: `components/ori/OriCompanion.tsx` (wrapper positioning, frame loop, section fly-to, park on bubble open, Wave on open, Celebrate on card open)

**Interfaces:**
- Produces `lib/ori/roam.ts`:
  - `type Box = { w: number; h: number }`, `type Viewport = { w: number; h: number; mobile: boolean }`, `type Vec = { x: number; y: number }`
  - `bounds(view: Viewport, box: Box, navH: number): { minX; maxX; minY; maxY }` — top-left positions keeping the box fully visible and below the navbar; mobile → `minY = view.h * 0.55`.
  - `pickWaypoint(view, box, navH, from: Vec, rand: () => number): Vec` — inside bounds, at least `min(view.w, view.h) * 0.25` from `from` (retry ≤ 8 times, then accept).
  - `type RoamState = { pos: Vec; vel: Vec; target: Vec; nextAt: number }`
  - `stepRoam(s: RoamState, dt: number, scrollDelta: number, now: number, opts: { stiffness: number; damping: number; scrollPush: number }): RoamState` — critically-damped spring towards target; `scrollDelta` (px since last frame) adds `-scrollDelta * scrollPush` to `vel.y` (content moves up → ORI is dragged, then springs back); result clamped by caller.
  - `clampTo(b: ReturnType<typeof bounds>, p: Vec): Vec`
- Produces `lib/ori/bus.ts`: `oriEmit(name: OriEvent, detail?)`, `oriOn(name, fn): () => void`; `OriEvent = 'open' | 'close' | 'card-open' | 'fly-to' | 'think' | 'reply'`; `fly-to` detail `{ selector: string; clip?: string }`.

  - `bounds` mobile 375×812 → `minY ≥ 812*0.55`.
  - `pickWaypoint` with seeded rand returns a point inside bounds and ≥ 0.25·min(w,h) from `from` (100 seeds).
  - `stepRoam` with target 300px away converges within 0.5px after 4s of 1/60 steps and never overshoots by > 5%.
  - `stepRoam` with `scrollDelta = 40` makes `vel.y` negative on that step.

- [ ] **Step 3:** Implement `roam.ts` and `bus.ts`. Defaults: stiffness 6, damping 2·√6 (critical), scrollPush 0.9 (desktop) / 0.5 (mobile); waypoint every 4–8 s (`nextAt`), mobile 7–12 s.

- [ ] **Step 5:** OriCompanion: wrapper becomes `fixed top-0 start... inset-0`-free `fixed left-0 top-0` with `transform: translate3d(x,y,0) rotate(bank)`; bank = clamp(vel.x·0.02, ±8deg). **Interfaces:**
- Consumes: `oriEmit/oriOn` from Task 1.
- Produces `lib/ori/catalog.ts`:
  - `type OriItem = { type: 'project' | 'service'; id: string }`
  - `type CatalogEntry = OriItem & { title: { en: string; ar: string }; line: { en: string; ar: string }; href: string /* external url, caseStudyUrl, or '#services' */ }`
  - `buildCatalog(projects: ProjectLike[], services: { en: ServiceCopy[]; ar: ServiceCopy[] }, ids: readonly string[]): CatalogEntry[]` (projects with `isPlaceholder` excluded).

- Dictionary `ori`: `{ talk, close, greeting, chips: { store, clinic, brand, work }, replies: { store, clinic, brand, work }, placeholder, send, privacy, thinking, fallback, limit, open: { project, service }, cardKind: { project, service } }` — greeting/chip copy exactly as spec §B2–B3; privacy exactly as spec decisions section.
